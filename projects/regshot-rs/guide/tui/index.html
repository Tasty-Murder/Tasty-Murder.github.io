    TUI¶

    regshot tui                                                          # start menu
regshot tui before.rshot after.rshot [more.rshot …] [--allow-view-mismatch]   # explorer

    Run with no snapshots, regshot tui opens a start menu over the working directory. It can open snapshots found there in the explorer, take a snapshot (Windows), compare to an HTML report, export an undo script or installer, import an upstream .hiv, show a snapshot's details, reopen a triaged set, or open the GUI or the settings file. Nothing loads until you choose, and each item shows the command it's equivalent to. With no terminal attached it prints its help and exits 2 instead of waiting for input.

    Given snapshots, it opens straight into the explorer described below.

    An interactive terminal explorer over the same diff engine as the HTML report, for working through a large diff without leaving the terminal. Every snapshot you pass is loaded at once. As everywhere else, snapshots captured with different WOW64 view sets are refused unless you pass --allow-view-mismatch.

timeline: every change across all snapshots
    • Snapshots (top left): every loaded snapshot. F and T mark the pair being compared in pairwise mode. Move with j/k while the rail is focused, and press ++enter++ to make the highlighted snapshot the new "to" side, with the one before it as "from".
    • Facets (bottom left): the change categories present, with counts. 1–5 show only that category and 0 clears the filter. Below them is how much of the current table you've triaged.
    • Changes (right): one row per change, showing its category, WOW64 view and path. The view column is what tells a 64-bit entry from its 32-bit namesake, which has the same path.
    • Detail (bottom right): the selected change, with its value on each side. REG_EXPAND_SZ values are also shown expanded when the snapshot recorded its environment.

    Pairwise and timeline¶

    s switches the change table between two views. The selection stays on the same change when it appears in both.

    • Pairwise (the default) lists what changed between the F and T snapshots, which start out as the last two.
    • Timeline lists everything that changed anywhere across all the loaded snapshots, with a states column holding one character per snapshot: + it appeared there, − it was removed, ~ its value changed, ● present and unchanged, blank absent. The category is the change's most recent one, a category filter keeps changes that went through that category at any point, and the detail pane shows the value at every snapshot.

    Keys¶

    Key Action
    j/k, ++up++/++down++ Move the selection (in whichever of the rail or table is focused)
    g / G First / last row
    ++ctrl+d++ / ++ctrl+u++ Half a page down / up
    ++tab++ / ++shift+tab++ Cycle focus: rail, table, detail
    ++enter++ (rail) Compare the pair ending at the highlighted snapshot
    s Toggle pairwise / timeline
    1–5, 0 Filter by category, clear the filter
    /, then ++enter++ Fuzzy search
    n / N Next / previous search match
    v Mark or unmark the selected change as triaged
    V Jump to the next change not marked yet
    X, X Clear every triage mark (the second X confirms)
    y Copy the selected path into the status line
    e Export an undo .ps1 for the current pair
    ? Help
    q, ++ctrl+c++ Quit

    Search¶

    / searches fuzzily, using the same matcher as the Helix editor: the characters you type have to appear in order in a row's path and value name, but not next to each other, so runupd finds …\CurrentVersion\Run\Updater. Matching ignores case. Search doesn't hide rows; it moves the selection. n/N step through the matches best first, where matches at the start of a path segment and longer unbroken runs rank higher. The search runs over the rows the table currently shows, so a category filter or a mode switch changes what it can find.

    Triage marking¶

    For a 100k-row registry diff, marking rows reviewed is more valuable than it is for a code review: work through the noise once, mark it, and V jumps to the next unexamined change (wrapping around). The facets pane counts how much of the current pair is triaged. X clears every mark, but only on a second X, and any other key cancels.

    Marks are saved as you make them, in a .regshot-triage-<hash>.json file next to the first snapshot. The hash covers the contents of every snapshot, in order, so reopening the TUI on the same snapshots brings the marks back, while a different set or a different order starts clean. The file disappears once nothing is marked. A mark records the change's view, path and value name, matched case-insensitively like the registry itself.

    regshot query <snapshots…> --triaged only|exclude reads the same file, listing just the changes you've marked, or just the ones you haven't looked at yet.

    Performance¶

    Real diffs have 100k–1M rows. The table holds only indexes into the timeline, not rendered rows, and each frame builds widgets just for the rows that fit on screen. Frame cost therefore depends on the terminal's size, not the diff's.

    Testing¶

    The TUI renders through ratatui's test backend in the crate's tests, so every layout change is checked with insta frame snapshots on Linux. That's where the picture above comes from.
