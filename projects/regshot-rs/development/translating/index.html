    Translating¶

    regshot-rs shows its interface in your language: the GUI, the start menu, the explorer (regshot tui), command-line messages, and the txt and html reports. This page explains how the translations are organised, and how to fix one or add a language.

    What gets translated, and what doesn't¶

    Translated Not translated
    GUI, start menu, explorer, help screens JSON, NDJSON/ECS, CSV, .reg, PowerShell, NSIS, Inno and .unl output
    txt and html reports .rshot files and anything else programs read
    Command-line messages people read: errors, progress, summaries --help, man pages and shell completions
    MCP tool descriptions (written for AI agents)
    Category codes (KEYADD, ValModi) and value types (REG_SZ)

    Everything in the second column is an interface other programs depend on, so it stays the same in every language.

    Error messages from deep inside regshot (for example, why a .rshot file couldn't be parsed) stay in English. The command-line message around them is translated, for example error: reading snapshot.rshot: ….

    "Upstream" means the language is one of the 29 in Regshot's own language.ini. regshot-rs takes the strings that mean the same thing in both programs from it, and the original translators are credited in the file. Everything else is machine-translated.

    Related tags fall back sensibly: zh-HK and zh-Hant get Traditional Chinese, nn and no get Norwegian Bokmål, sr (Cyrillic too) gets Serbian in Latin script, and pt gets Brazilian Portuguese unless a region says otherwise. regshot config --migrate regshot.ini carries over upstream's [Setup] Language= setting.

    Choosing a language¶

    regshot picks the first of these that is set:

    1. --lang de on the command line, or the REGSHOT_LANG environment variable.
    2. language = "de" under [ui] in the settings file. The GUI reads this too.
    3. Your system's language.
    4. English.

    A regional tag falls back to its language. For example, de-AT uses German. auto means "use the system language".

    Where the text lives¶

    Each language is one file, crates/regshot-i18n/locales/<tag>.ftl, in Fluent format. The files are built into the program, so nothing extra is installed. en.ftl is the source: every other file uses the same message IDs.

    A message is an ID, =, and the text:

    gui-button-open = Open snapshots…
tui-yanked = yanked: { $path }

    { $path } is a placeable, a value regshot fills in. Keep every placeable from the English message, spelled exactly the same. You can move it to wherever your language's word order needs it.

    Plurals¶

    When a message depends on a number, it lists one form per plural category. English has two, one and other:

    tui-all-triaged =
    { $count ->
        [one] the only row is triaged
       *[other] all { $count } rows are triaged
    }

    Use your language's own categories. Russian uses one, few, many and other. Arabic uses zero, one, two, few, many and other. Japanese needs only other. The CLDR plural rules table lists them for every language. The variant marked with * is the fallback, and one variant must have it.

    Things to leave as they are¶

    • Commands, flags and file names: `regshot export`, --view 64, .rshot, host:port.
    • Key names in brackets: [capture], [ui] language.
    • (NULL!), category codes, and value types.
    • The keyboard keys in the explorer's help (j/k, Ctrl-d). Only their descriptions are messages.

    Fixing or adding a translation¶

    1. Edit crates/regshot-i18n/locales/<tag>.ftl. To add a language, copy en.ftl to <tag>.ftl, translate it, and add one line for it to LANGUAGES in crates/regshot-i18n/src/lib.rs: the tag, the language's name in itself, and whether it's written right to left.

    2. Check it:

      cargo test -p regshot-i18n

      This fails if a file doesn't parse, uses an ID English doesn't have, or uses different placeables from English. A message you leave out isn't an error: English is shown for it instead.

    3. Look at it: run cargo run -p regshot-cli -- --lang <tag> tui for the start menu, add tui a.rshot b.rshot for the explorer, or set [ui] language and start the GUI.

    4. For Chinese, Japanese or Korean, cargo test -p regshot-gui also checks that the GUI's bundled font has every character you used. If it fails, rebuild the fonts with crates/regshot-gui/assets/fonts/subset.sh (needs the GitHub CLI and fonttools).

    Most of every translation is machine-generated, and each file's header says so. The exceptions are messages marked # imported: those come from upstream Regshot's language.ini, written by the people the header credits. Where an imported string was fixed (characters lost to an old codepage, a misspelling, a wrong word), the mark says # imported (corrected: …), and the test that checks imports against language.ini lists the same reason. Corrections from native speakers are very welcome.

    For developers: adding a message¶

    • Show text with tr!("id"), or tr!("id", name = value) with arguments. Pass counts as numbers, not formatted strings, so plurals work.
    • Add the English message to en.ftl under the section for its surface. Prefixes: common-, gui-, menu-, tui-, cli-, report-.
    • Write whole sentences as one message. Don't build format!("{what} can't be empty") out of translated pieces, because word order differs between languages.
    • Pad terminal columns with regshot_i18n::pad_to or aligned_rows, not {:<N}. A Chinese or Japanese character is two columns wide.
    • cargo test -p regshot-i18n checks that every "id" in the sources exists in en.ftl, and that every message in en.ftl is used somewhere.
    • In the GUI, show translated text through the theme helpers (theme::label, theme::dim, theme::field and the buttons) or bidi::display, and data such as paths and labels through theme::data. They lay Hebrew and Arabic out right to left, which egui can't do itself. Arrange rows with theme::row and theme::trailing_row, so they mirror in those languages.
    • To see the result, cargo test -p regshot-gui --test screenshots -- --ignored renders the window in several languages to docs/images/gui/ (it needs a GPU, or Mesa's software renderer).
