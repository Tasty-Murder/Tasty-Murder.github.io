    Architecture¶

    Workspace layout¶

    regshot-rs/
├── crates/
│   ├── regshot-core/      # model, interning, diff engine — no OS deps, fully tested
│   ├── regshot-capture/   # Win32 registry scanner (cfg(windows)); synthetic source for tests
│   ├── regshot-report/    # template engine + HTML/text/reg/ps1/nsis/json emitters
│   ├── regshot-config/    # the settings file: model, location, loading, regshot.ini migration
│   ├── regshot-mcp/       # MCP server (stdio + streamable HTTP)
│   ├── regshot-tui/       # ratatui interactive explorer
│   ├── regshot-cli/       # the `regshot` binary — hosts the TUI too
│   └── regshot-gui/       # `regshot-gui` binary: egui shell (snapshots, capture, compare, export)
├── docs/                  # this site
└── .github/workflows/

    regshot-core, regshot-report, and regshot-mcp's analysis half build on any platform. Only regshot-capture's Win32 backend is Windows-gated — so a Linux build can still load and compare .rshot files captured elsewhere, a capability upstream Regshot lacks entirely. This is also why development happens primarily on Linux: the core model, diff engine, template engine, and TUI are all testable without Windows at all.

    The core data model¶

    Upstream Regshot's comparison mutates an in-place match flag on a linked tree during comparison — correct for two snapshots, structurally incapable of a third. regshot-rs starts from the opposite shape: immutable, flat, sorted arrays.

    pub struct Snapshot {
    pub meta:   SnapMeta,
    pub keys:   Box<[KeyEntry]>,    // sorted by PathId
    pub values: Box<[ValueEntry]>,  // sorted by (PathId, NameId)
    pub blobs:  BlobStore,
}

    Comparing snapshots is then a merge-join: linear in the total number of entries, and the same sweep whether you're comparing 2 snapshots or 20 — advance N cursors, emit one row per entity, derive its category from the transition. Every category (KeyAdd, KeyDel, ValAdd, ValDel, ValModi) is derived, never stored: Absent → Present is an add, Present → Absent is a delete, Present{h1} → Present{h2} with different hashes is a modification.

    Interning and WOW64 views¶

    Paths and value names are interned — case-folded for identity (fixing upstream's real case-sensitivity bug) while the interner keeps the first-seen spelling for display. Critically, every interned path is rooted under a RegView (registry-views.md), so HKLM\Software\Foo read through the 64-bit view and through the 32-bit view intern to two different, never-aliasing ids. The fabricated-changeset bug that motivated modeling views at all is prevented at the type level: there is no code path where a 32-bit-view entity can accidentally match a 64-bit-view one.

    The timeline¶

    pub type State = Option<NonZeroU64>;   // presence + a content hash, or absence

pub struct TimelineMatrix {
    n_snapshots: usize,
    entities:    Box<[EntityId]>,
    states:      Box<[State]>,   // flattened row-major, stride n_snapshots
}

    One allocation for the whole matrix rather than one small collection per row — at a million rows that difference is the whole ballgame. TimelineMatrix::changes(from, to) gives the pairwise view any two snapshots in the set; the same matrix serves the N-way timeline view without a second data path.

    Testing philosophy¶

    The diff engine gets two independent checks: a deliberately slow, obviously-correct O(n·m) nested-loop oracle, and proptest-generated snapshot pairs asserting the fast merge-join agrees with it on every input. Beyond agreement, a handful of properties are checked explicitly, including the one that matters most for a tool whose output undoes changes on a live system: undo(diff(s1, s2)) applied to s2 reconstructs s1 exactly. See the testing module and tests/ in regshot-core for the generator and the property suite.

    Platform capture boundary¶

    pub trait RegistrySource {
    type Error: core::error::Error + From<IdSpaceExhausted>;
    fn walk<S: KeySink>(&self, hive: HiveRoot, view: RegView, sink: &mut S) -> Result<(), Self::Error>;
}

pub trait KeySink {
    type Key: Copy;
    fn root(&mut self, view: RegView, hive: HiveRoot) -> Result<Option<Self::Key>, IdSpaceExhausted>;
    fn key(&mut self, parent: Self::Key, name: &str) -> Result<Option<Self::Key>, IdSpaceExhausted>;
    fn value(&mut self, key: Self::Key, name: &str, kind: RegType, data: &[u8]) -> Result<(), IdSpaceExhausted>;
}

    Generic over the sink (static dispatch), because the callback is invoked millions of times during a real scan: a dyn vtable hop per key/value is not free enough to pay for the whole registry. The sink hands back its own Key for each key, an interned path in the snapshot's case, and the walk passes it back for that key's values and subkeys. So the walk never builds a full path, and returning None for a key skips its whole subtree without reading it.

    The walk itself is written once, in regshot-capture's walk module, against RawRegistry: the few calls a walk needs (open a key, query its buffer sizes, enumerate subkeys and values). On Windows, NtSource implements those calls over ntdll and Win32Source over the Reg* API. Capture uses NtSource wherever it reads a view exactly as the Reg* API does: every view except the 32-bit one in a 64-bit process, where only the Reg* layer redirects. tests/live_registry.rs checks that on every Windows architecture CI runs. SyntheticSource, an in-memory tree, implements them everywhere, so tests and benchmarks run the real walk on any platform. One set of buffers serves a whole walk, and names are decoded into a reused string, so a key or value costs no allocation of its own.

    Capture walks each hive in parallel (walk_parallel): rayon workers read the keys near the root, and the subkeys of wide keys, into compact logs, and the calling thread replays the logs into the sink in the single-threaded walk's order. So the sink needs no locking, and a snapshot doesn't depend on the thread count.

    Skip and whitelist patterns are compiled once into a small trie (regshot-capture's filter module). Each key's sink Key carries its position in that trie, so matching a key costs a comparison or two.

    cargo bench -p regshot-capture measures everything except the registry calls: it walks a generated registry shaped like a real HKLM (about 106k keys and 161k values) and builds the snapshot.
